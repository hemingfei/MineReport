# 研报业务身份用标题+券商+日期组合键（含已知误合并风险）

研报去重有两层可选：文件字节哈希（确定性事实，但同内容转码后哈希即变）与业务语义组合键（标题+券商+发布日期）。我们决定**业务身份采用纯组合键：同(标题, 券商, 发布日期)自动判为同一篇研报，后续来源的文件并入该研报**；文件层的 SHA-256 仅作为普通属性存储，不做唯一约束。

这是用户明确坚持的选择（2026-09 grilling，工单 #7），已知并接受的权衡：

- **误合并风险**：券商同日发两篇同标题不同内容的报告（如每日晨报、同时点评多标的的分册）会被并成一篇。缓解：入库时标题做去空白/全半角归一；若实际遇到误合并，靠人工拆分处理。
- **换来的好处**：跨渠道的转码版（官网 PDF vs 平台转码 PDF，字节不同内容相同）自动归到同一研报下，不产生重复条目，也不需要"疑似重复人工确认队列"的额外流程。

## Considered Options

- 内容哈希做文件层硬约束 + 业务键软提示（被否：多一个人工确认队列流程，用户判断该场景低频）
- 按输入集合指纹（用于综合分析身份，与本题无关）
